¿Por qué existen tantos lenguajes?

Porque cada lenguaje es una respuesta a un problema distinto, y ninguno puede ser el mejor en todo a la vez.

Un lenguaje es un acuerdo entre personas y máquinas. Cuando cambia dónde corre el código, qué tan caro es un error o quién lo va a mantener, cambia también el acuerdo que conviene. Hay cuatro fuerzas que explican casi toda la variedad:

1. Dónde corre

El navegador sólo ejecuta JavaScript (y WebAssembly). iOS favorece Swift, Android Kotlin. Una base de datos entiende SQL. El entorno decide antes que tú.

navegador → JS · iPhone → Swift · chip → C

2. Qué optimiza

Velocidad de la máquina, velocidad del equipo o seguridad ante errores. Mejorar una casi siempre cuesta otra: Rust es rápido y seguro, pero lento de aprender; Python es rápido de escribir, pero más lento al ejecutar.

rendimiento ↔ productividad ↔ seguridad

3. Qué describe

No todos dan órdenes paso a paso. SQL pregunta por datos, HTML describe estructura, YAML describe infraestructura, Protobuf describe un contrato. Son lenguajes declarativos: dices qué quieres, no cómo lograrlo.

imperativo: “haz esto” · declarativo: “quiero esto”

4. Historia y ecosistema

Reescribir cuesta. COBOL todavía procesa operaciones bancarias, Java domina sistemas empresariales por sus librerías y talento disponible, y Python ganó la IA porque ahí estaban las herramientas.

librerías + comunidad + gente contratable

Algunos lenguajes cruzan capas

Cómo elegir

Seis preguntas antes de escoger un lenguaje

  • ¿Dónde va a correr?

    Navegador, teléfono, servidor, base de datos o un chip. Muchas veces esta respuesta ya elige por ti.

  • ¿Qué es más caro: la máquina o el equipo?

    Si pagas mucho cómputo, Go o Rust ahorran dinero. Si el cuello de botella es entregar rápido, Python o TypeScript ganan.

  • ¿Cuánto cuesta un error?

    En pagos, un error es dinero. Ahí convienen tipos estrictos, transacciones y compiladores que se quejan antes de producción.

  • ¿Qué sabe tu equipo y a quién puedes contratar?

    El mejor lenguaje en papel pierde frente al que tu equipo domina y el mercado ofrece.

  • ¿Qué ecosistema ya existe?

    Librerías, integraciones y contrapartes. Si el banco sólo habla SOAP, hablarás SOAP.

  • ¿Cuánto tiempo va a vivir?

    Un prototipo de dos semanas y un sistema que operará quince años piden decisiones distintas.

No necesitamos tantos lenguajes porque sí. Los necesitamos porque un producto real tiene muchas capas, y cada capa tiene un problema distinto que resolver.
